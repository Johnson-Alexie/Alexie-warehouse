## 图形处理知识

### 一、val loss 衡量的是什么

**val loss 衡量的是模型对“没见过的图”的预测误差。**

验证集的图 **从来没参与过训练** ，模型没背过它们。所以：

- 模型在验证集上表现好 → 说明它学到的是 **通用规律** （“装甲板是这种形状、这种纹理”），换张新图也灵
- 模型在验证集上变差 → 说明它学到的东西 **对新图没用**

**val loss 上升 = 模型学到的东西，对“新图”的帮助在变小。**

val loss 里其实装了 **三块具体的东西**

| loss           | 衡量的“错”                                    |
| -------------- | --------------------------------------------- |
| `val/box_loss` | 框 **位置** 错多少（框偏了、大小不对）        |
| `val/cls_loss` | **类别** 判错多少（红色认成蓝色、置信度给错） |
| `val/dfl_loss` | 框 **边界** 的精细度差多少                    |

**所以更精确的说法是：**

> **val loss 低 = 模型在新图上，框得准、类别分得对、边界抠得细。**
>  **val loss 高 = 这些方面在新图上出错多。**

**更准确的说法：“val loss 反映了模型学到的东西，在没见过的图上犯错有多少。”**

#### 二、为什么初期 val loss 一直降

训练刚开始，模型是“一张白纸”，什么都不懂。

**这个阶段** ，训练集里 **到处都是有用的通用规律** ：

- “亮红色区域大概率是装甲板”
- “圆形灯珠的排列是特征”
- “这类纹理和背景要区分开”

模型每挨一轮打（计算 loss → 反向传播 → 更新权重），就学到几条这样的规律。 **这些规律对新图同样适用** ，所以 val loss 跟着降。

**这阶段训练集和验证集在“一起变好”，因为学的是真本事。**

#### 三、关键转折：通用规律学完了

到第 40 轮左右，模型已经把这 86 张图里 **所有能通用化的规律** 基本学完了（你 mAP 都 0.99 了，就是这个意思）。

**但是训练不会自己停，它还在继续。**

这时训练集上还剩什么“可学”的东西？只剩下 **那些只对训练集本身有用、对新图没意义的内容** ：

| 训练集里“剩下”的东西                | 为什么对新图没用 |
| ----------------------------------- | ---------------- |
| 这张图背景的 **具体纹理**           | 验证集背景不一样 |
| 那次拍摄的 **光照亮度**             | 验证集光照不同   |
| 装甲板 **偏了 2 个像素** 的具体位置 | 每个位置都不同   |
| 某张图 **特有的噪点**               | 新图没这个噪点   |

**模型为了继续降低训练集的 loss，就会开始去“抓”这些细节。**  这些细节在训练集上确实能降低 loss（因为它见过）， **但换个新图，全都对不上号 → val loss 反而上升。**

#### 四、一句话的本质

**过拟合的本质是“学习资源错配”：**

> 前 40 轮，模型学习的是  **“规律”** （能迁移到新图）→ 训练集、验证集双赢
>  后 10 轮，模型能学的“规律”没了，只好学习  **“噪声”** （只对训练集有用）→ 训练集继续降、验证集反升

**所以：val loss 上升，就表示模型从“学规律”转向“记细节”了。**  这个转折点就是过拟合的起点。

#### 五、为什么“记细节”对训练集有效、对新图有害

这是个常见疑问。为什么记细节会让 val loss 变“差”，而不是“不变”？

因为模型的 **容量有限** ，而这部分容量被这些细节占了：

假设模型有 100 份“注意力”：

```
合理分配：90 份学通用特征 + 10 份学细节噪声 → 验证集最好
过拟合后：60 份学通用特征 + 40 份学细节噪声 → 通用特征被挤掉，验证集变差
```

**它不是“记住细节”这么简单——是“为了记细节，把本来该学通用特征的精力挤占了”。**  所以 val loss 是 **上升** ，不是持平。

这就是为什么过拟合的模型表现会变差：模型把更多注意力放在了只对训练集有用的细节上，对通用特征的关注就变少了。





### MAP是什么

**mAP = mean Average Precision（平均精度均值）**

这是目标检测里 最核心的评价指标 ，一个数字概括“模型框得准不准、分得对、漏不漏”。


名字拆成三层理解，从底层讲起。

#### **第一层：Precision 和 Recall**

先得懂这两个，mAP 才有意义。还记得混淆矩阵吗？

|            | 预测有       | 预测无     |
| ---------- | ------------ | ---------- |
| **实际有** | TP（真阳性） | FN（漏检） |
| **实际无** | FP（误检）   | TN         |

**Precision（精确率）= 你框出来的，有多少是真对的**

Precision = TP / (TP + FP)
           = 报出的对的数量 / 报出的全部数量

“你说是装甲板的框里，有几个真的是”  —— 高 Precision = 很少误报。

**Recall（召回率）= 真有的，你抓到了多少**

Recall = TP / (TP + FN)
       = 抓到的对的数量 / 实际全部数量

“真实装甲板里，你找到了几个”  —— 高 Recall = 很少漏检。

这对指标天然矛盾 ：想全抓住（Recall 高）就容易乱抓（Precision 低）；想框得准（Precision 高）就容易漏（Recall 低）。



#### 第二层：AP —— 一个类别的“综合成绩”

既然是矛盾的，怎么用一个数评价？

**做法：把置信度阈值从高到低扫一遍，每个阈值下算一对 (Precision, Recall)，画成 PR 曲线，曲线下的面积就是 AP。**

```
P
1 |‾‾‾‾‾‾‾‾‾‾╮
  |          ╰‾‾╮
  |             ╰‾‾
  +----------------→ R（1）
   ←— 曲线下面积 = AP —→
```

**AP（Average Precision）= PR 曲线下的面积，越接近 1 越好。**

**为什么用面积？**  因为它同时奖励了“高 Precision”和“高 Recall”——曲线越往右上角贴，面积越大，说明 **在各种阈值下整体都好** 。



#### 第三层：mAP —— 多个类别的平均

**mAP = 所有类别 AP 的平均值。**

```
mAP = (AP_armor_red + AP_armor_blue) / 2
```

你是两类（红、蓝），所以 mAP 就是这两个 AP 求平均。

**这就是那个 “m” 的意思——mean（平均）。**  类别越多，m 平均的项越多。

**最关键：mAP50 和 mAP50-95 的差别**

**“50”和“50-95”指 IoU 阈值。**

先解释  **IoU（交并比）** ：

```
IoU = 框和真实框的重叠面积 / 两者合并的总面积
```

| IoU 值 | 含义                                     |
| ------ | ---------------------------------------- |
| 0.5    | 框和真实框至少一半重叠 →  **算作对**     |
| 0.9    | 框必须和真实框几乎完全重合 →  **才算对** |

iou 越大，要求框得越准，越严格

| 指标         | IoU 怎么取值                                       | 要求                        |
| ------------ | -------------------------------------------------- | --------------------------- |
| **mAP50**    | 只在 IoU=0.5 一个点算                              | **宽松** ，框得差不多就算对 |
| **mAP50-95** | IoU 从 0.5、0.55、…、0.95（10 个点）分别算，再平均 | **严格** ，框得粗了分低     |

**所以：**

- **mAP50**  = 框得“差不多对”的能力
- **mAP50-95**  = 框得“越来越精细”的平均水平

#### **为什么用 mAP 而不是直接看 P 和 R**

| 只用 P、R 的问题            | mAP 的好处                 |
| --------------------------- | -------------------------- |
| P 和 R 是矛盾的，没法单独比 | 积分成面积，综合两者       |
| 只看某个阈值，不代表全貌    | 扫过所有阈值，反映整体能力 |

#### 一句话总结

> **P 管“报的准不准”，R 管“有没有漏”，AP 是它俩的综合成绩，mAP 是所有类别的平均。**
>  **mAP50 宽松、mAP50-95 严格，后者更能看出框的精细程度。**





### 1.**过拟合是什么**

想象两个学生准备同一场考试：

**学生 A（正常学习）**
 做练习题时，他理解了解题思路。考试遇到 **新题** ，也能做出来。

**学生 B（死记硬背）**
 他把练习册的 **每道题连答案数字都背下来** 了。一翻练习册，全对。但考试换了道新题，他傻眼了。

**学生 B 就是过拟合。**

放到模型上

|            | 正常                   | 过拟合                            |
| ---------- | ---------------------- | --------------------------------- |
| 训练集表现 | 好                     | **极好** （几乎 100%）            |
| 验证集表现 | 也好                   | **变差**                          |
| 本质       | 学到了“装甲板长什么样” | 学到了“这张图第 320 像素有个红点” |

过拟合的模型，它记住的就是你 **这 86 张训练图的细节** ，训练集就是它的练习册；它记住的是 **每张图的具体像素、背景、光照** ，并没有学到通用特征，换一张新图（比如换个场地、换个光照），它就认不出来了。

## 

**发现过拟合怎么办**

实际做法很简单，三选一：

- **减少轮数** ：50 轮改 30 轮（最省事）
- **加数据** ：多标几十张图（最有效，但要花时间）
- **早停（early stopping）** ：YOLO 自带这个选项

第三条可以加个参数：

```
yolo train data=armor_dataset.yaml model=yolo26n.pt epochs=50 patience=15 ...
```

`patience=15` 的意思是： **如果验证集指标连续 15 轮没有进步，就自动停下来** ，不用跑满 50 轮。这是标准做法。

**patience 怎么判断“指标有没有进步？**

这是核心问题。YOLO 的判断逻辑是：


盯住一个“总指标”，每轮训练后比较它有没有比之前的最高值更高。


默认盯的是  **fitness** ，它是一个加权组合分数：

`fitness = 0.1 × mAP50 + 0.9 × mAP50-95`



**为什么给 mAP50-95 权重更高（0.9）？**

- mAP50 比较宽松：框有 50% 重叠就算对，容易很快冲到 0.99，拉不开差距。

- 
  mAP50-95 更严格：要求框重重叠从 50% 到 95% 都要准，更能反映“框贴得准不准”。




所以 fitness 主要看  mAP50-95  的表现—— 这也是 best.pt 的选择标准 。





### **2. 虚拟机 CPU 分配认知问题**

- 不清楚 VMware 里 `Number of processors` 和 `Number of cores per processor` 两个选项的关系
- 误以为“内核越多越好”，想直接分 32 核
- 最终正确配置： **1 processor × 8 cores = 8 核**



### **3.虚拟机 CPU 配置**

| 知识点                           | 说明                                                     |
| -------------------------------- | -------------------------------------------------------- |
| 总核数 = 处理器数 × 每处理器核数 | 1 × 8 = 8 核                                             |
| `Number of processors` 要设为 1  | 多 processor 会模拟多插槽/NUMA，多线程库调度变差         |
| 核心数不应超过物理核心数         | 超了会争抢真实 CPU 时间片，反而更慢                      |
| 推荐给一半或留 2~4 核给宿主机    | 宿主机 Windows 也要跑界面                                |
| `nproc` 看虚拟机核数             | 输出 8 表示生效                                          |
| `lscpu` 中文系统字段被本地化     | `Socket/Core` 英文 grep 匹配不到，要找“座”“每个座的核数” |

#### 4.`F1_curve.png` —— 找最佳置信度阈值

这张图不评价模型好坏，它回答的是： **推理时置信度阈值该设成多少？**

**先回顾 F1 是什么**

**F1 score 是 Precision 和 Recall 的调和平均：**

```
F1 = 2 × (P × R) / (P + R)
```

**它把 P 和 R 合并成一个数。**  只有 P 和 R 都高，F1 才高；任何一项偏低，F1 都会被拉下来。

**为什么要用调和平均而不用算术平均？**  因为两者矛盾，一个高一个低时，算术平均会虚高；调和平均更偏保守，能压住这种虚高。

**这张图长什么样**

**横轴是置信度阈值（confidence），纵轴是 F1 值，曲线通常是个先升后降的峰。**

```
F1
1 |
  |        ╭──╮
  |      ╭─╯  ╰─╮
  |    ╭─╯      ╰──╮
  |  ╭─╯            ╰────
  +------------------------→ conf
   0.0   0.2   ↑   0.6   1.0
             峰值
```

**曲线峰值对应的横坐标，就是最佳置信度阈值。**

**为什么是“先升后降”**

| 置信度阈值        | 会发生什么               | P    | R    | F1       |
| ----------------- | ------------------------ | ---- | ---- | -------- |
| **太低** （0.01） | 什么框都报，垃圾框也留着 | ↓ 低 | ↑ 高 | 低       |
| **适中** （峰值） | 好的留下，烂的滤掉       | 平衡 | 平衡 | **最高** |
| **太高** （0.9）  | 只留极确信的，漏掉很多   | ↑ 高 | ↓ 低 | 低       |

**两端都差，中间最好，所以曲线是个鼓包。**

**YOLO 会在这张图上标出一个红点（或标注 `confidence=xxx`），那就是自动选出的 F1 最大点。**

**这张图对你实际部署的价值**

**你实际跑检测时，必须给一个 `conf=` 参数。这张图就是告诉你该填多少。**

**怎么用：**

- 找到图上红点/峰值对应的 conf 值，通常 YOLO 默认推荐 0.25 附近
- 你的模型如果峰值在 0.3~0.5 之间， **部署时填这个值**



**误解：“置信度不应该在训练前就设置好吗”**

训练和推理是两回事，两个阶段各有一个“置信度参数”，但含义完全不同。

| 阶段          | 参数               | 作用                                            | 常用值    |
| ------------- | ------------------ | ----------------------------------------------- | --------- |
| **训练**      | `conf`（基本不用） | 训练时 **不设置信度阈值** ，loss 计算用全部预测 | —         |
| **验证/推理** | `conf`             | **过滤掉低分框** ，只留超过阈值的               | 默认 0.25 |

**训练时模型输出的是“每个框 + 每个类别的概率分数”，它不知道你要用多少分当门槛。**  门槛是 **推理时才施加的规则** ，训练阶段根本不需要它。

**你训练时如果真设了 `conf=`，那个参数在训练里基本不生效** ——它只影响验证阶段的评估输出，不影响模型权重。

**所以这张图的用途是**

**它帮你决定“推理时的 conf 该填多少”。**

说得对的一点是：训练前确实不知道用什么值。  而这正是这张图存在的意义， 它用训练好的模型在验证集上扫一遍所有阈值，**告诉你哪个值最好**。

**所以流程图是：**

```
训练完成 → 生成 F1_curve → 从图上读出最佳 conf → 部署时用这个值
```

**它是“训练后、部署前”的中间产物，不是训练前的设置项。**



#### 5.`PR_curve.png` —— Precision-Recall 曲线

这张图是 **计算 mAP 的核心依据** ，也刚好承接上一张 F1 的心智模型。

**横轴 Recall（召回率），纵轴 Precision（精确率），一条从左下角弯向右上的曲线。**

```
P
1 |‾‾╮
  |  ╰‾╮
  |    ╰‾╮
  |      ╰‾╮
  |        ╰‾‾╮
  |           ╰──╮
  +---------------→ R
  0                1
```

**理想情况：曲线贴着右上角（P=1，R=1），围成满格面积。**
 **实际情况：曲线会在某个地方往下掉。**



**为什么是这么个形状**

**回想 F1 那张图：置信度阈值从低到高扫，P 和 R 此消彼长。**

**PR 曲线其实就是把同一个扫描过程换了个画法：**

| conf 阈值         | 状态                      | 对应曲线上的位置         |
| ----------------- | ------------------------- | ------------------------ |
| **很低** （0.01） | 什么都报，R 高但 P 低     | **右下角** （R≈1，P 低） |
| **很低 → 升高**   | 好的留下，烂的淘汰        | **沿曲线往左上走**       |
| **很高** （0.9）  | 只报极确信的，R 低但 P 高 | **左上角** （R 低，P≈1） |

**所以曲线的两个端点：右下 = 全报，左上 = 只报最稳的，中间 = 各种阈值下的折中。**

**曲线越往右上看，模型越好。**



**和 mAP 的直接关系**

**mAP 就是把这条 PR 曲线下的面积算出来，再对所有类别取平均。**

```
mAP = ∫ PR 曲线下的面积 dR
```

**这就是第一张图 `mAP50=0.995` 的来源。**  曲线几乎贴着右上角，面积接近 1，所以 mAP 接近满分。

"mAP50 和 mAP50-95" 的差别，也在这里体现：

| 指标         | PR 曲线怎么算                                         |
| ------------ | ----------------------------------------------------- |
| **mAP50**    | IoU 只用 0.5 判对错，画 **一条**  PR 曲线，算面积     |
| **mAP50-95** | IoU 从 0.5 到 0.95  **各画一条** ，算 10 个面积再平均 |

**IoU 越高，判对越严，PR 曲线整体越往左下缩，面积越小。**  所以 mAP50-95 低于 mAP50 是必然的。

**一句话收尾**

> **PR 曲线是 mAP 的图形化来源：它把“阈值扫描下 P 与 R 的此消彼长”画成一条弧，弧越贴右上角，面积越大，mAP 越高。你的曲线接近完美方角，这就是 0.995 的证据。**





### 置信度和loU的区别

IoU 和置信度是模型输出里两套独立的数字，作用也不同。

|                  | **置信度（conf）**             | **IoU**                              |
| ---------------- | ------------------------------ | ------------------------------------ |
| **回答什么问题** | “这个框里 **是不是有目标** ？” | “我画的框和真实框 **对得准不准** ？” |
| **谁给的**       | **模型自己** 算出来的          | **评估时** 才计算，模型不知道        |
| **取值范围**     | 0 ~ 1（概率）                  | 0 ~ 1（重叠比例）                    |
| **用在哪**       | **推理阶段** 过滤框            | **训练评估** 时判对错                |

#### 置信度是什么

**模型每画一个框，会给它附一个分数：**

```
框1: [x,y,w,h]  conf=0.95  class=armor_red   ← 我很确信这里有红装甲板
框2: [x,y,w,h]  conf=0.30  class=armor_blue  ← 可能是，但不太确定
框3: [x,y,w,h]  conf=0.02  class=armor_red   ← 大概率是背景噪声
```

**`conf=0.95` 的意思不是“框得准”，而是“我确信这里有目标”。**  至于框得准不准，要看 IoU。

#### IoU 是什么

**IoU（Intersection over Union，交并比）是评估时，把“预测框”和“真实标注框”画在一起比**

- 完全重合 → IoU = 1.0   
- 完全不挨 → IoU = 0.0    
- 一半重叠 → IoU ≈ 0.5

`IoU = 交叠面积 ÷ 总面积`，衡量两个框“贴得多紧”。

只有评估时才知道真实框在哪，所以 IoU 是评估指标，模型训练时看不到它。



**它们怎么配合判断“对错”**

**一个预测框要被判为“正确（TP）”，必须同时满足两个条件：**

```
条件1：conf ≥ 阈值        （模型自己觉得够可信）
条件2：与某真实框 IoU ≥ 0.5（位置对得够准）
```

**两个条件缺一不可：**

| 情况             | conf | IoU  | 判定             |
| ---------------- | ---- | ---- | ---------------- |
| 又确信又框得准   | 0.95 | 0.8  | ✅ TP             |
| 确信但框歪了     | 0.95 | 0.2  | ❌ FP（误检）     |
| 框准但模型不确信 | 0.2  | 0.8  | 被阈值筛掉，不算 |

**回到你的 mAP50 vs mAP50-95**

**现在这个差别就清楚了——差别只在 IoU 门槛：**

| 指标         | IoU 门槛                                  | 含义             |
| ------------ | ----------------------------------------- | ---------------- |
| **mAP50**    | IoU ≥  **0.5**  就算对                    | 框到大概位置就行 |
| **mAP50-95** | IoU 从  **0.5 到 0.95**  逐档严查，取平均 | 框必须越来越精准 |

**你的 mAP50=0.995（宽松时几乎满分），mAP50-95=0.873（严格后下降）** ，意思是：

> **模型“找到了”目标这件事做得很好，但“框得极其精确”还有提升空间。**

**尤其 blue 类：mAP50=0.995，但 mAP50-95 只有 0.802** ，说明蓝色装甲板 **都能找到，但框的边界贴得不够准** ——大概率是样本少（只有 9 个实例），框的尺度学得不够好。

| 概念        | 谁产生       | 什么时候用 | 回答了啥   |
| ----------- | ------------ | ---------- | ---------- |
| **置信度**  | 模型         | 推理过滤   | 有没有目标 |
| **IoU**     | 评估时算     | 判 TP/FP   | 框得准不准 |
| **F1 曲线** | 扫 conf 阈值 | 选部署参数 | 阈值设多少 |
| **PR 曲线** | 扫 conf 阈值 | 算 mAP     | 整体好坏   |

**一句话总结：**

> **置信度是“敢不敢报”，IoU 是“报得准不准”。模型只负责给你置信度，IoU 是事后裁判用它和标准答案比对算出来的分。**



**一个容易混淆的点，顺便说清**

**IoU 在训练和评估阶段都会用到，但用途不同：**

| 阶段     | IoU 用来干什么                          |
| -------- | --------------------------------------- |
| **训练** | 算 loss（边界框回归损失、正负样本匹配） |
| **评估** | 判 TP/FP，算 P、R、mAP                  |

**但无论哪个阶段，模型输出的都只有置信度和框坐标，IoU 都是“外部计算”出来的。**  模型不直接输出 IoU。

#### **准确理解：**

> **置信度是模型给候选框打的“类别 + 可信度”标签，推理时用它筛框、定类；IoU 是评估时裁判拿预测框和标准框比对，判断位置准不准。两者一个管“敢不敢报”，一个管“报得准不准”。**



### NMS是什么，有什么用

**NMS = Non-Maximum Suppression，非极大值抑制**

**一句话：同一个目标，模型可能画出好几个框，NMS 负责只留最好的那一个，把重复的删掉。**

#### 为什么需要它

**模型在检测时，不是“找准一个框”，而是“撒一堆候选框”。**  一块装甲板周围，模型可能同时给出：

```
框1: [略偏左]  conf=0.92
框2: [略偏右]  conf=0.88
框3: [略大]    conf=0.75
框4: [略小]    conf=0.60
```

**这 4 个框都指同一块装甲板，都超过了 conf 阈值，如果全输出，图上就会叠 4 个框，乱成一团。**

**NMS 的作用就是：留下 0.92 那个，其余 3 个删掉。**

#### 具体怎么做的

```
1. 把所有框按置信度从高到低排序
2. 取置信度最高的框 A，保留它
3. 计算 A 和其他所有框的 IoU
   → IoU 超过阈值的（说明是同一个目标）→ 删掉
   → IoU 低于阈值的（说明是不同目标）→ 留着
4. 从剩下的框里再取最高分，重复步骤 2~3，直到没有框
```

**所以 IoU 不只在评估时用，NMS 里也用它判断“两个框是不是在指同一个东西”。**

#### 两个关键参数

**NMS 的行为由两个阈值控制：**

| 参数                      | 含义                     | 调大 →                       | 调小 →                   |
| ------------------------- | ------------------------ | ---------------------------- | ------------------------ |
| **`conf`**                | 先筛掉低分框（NMS 之前） | 框更少、更保守               | 框更多、更激进           |
| **`iou`（NMS IoU 阈值）** | 判断“两个框算不算同一个” | 删得更狠，密集目标可能被误删 | 删得更松，可能留下重复框 |

#### 一句话总结

> **NMS 是推理时的“去重员”：按置信度排队，从高分开始保留，凡是和已保留框 IoU 过高的（说明指同一个目标）全部删掉。它保证一个目标最终只输出一个框，让结果干净可读。**



### Faster R-CNN 是什么

一句话：Faster R-CNN 是深度学习目标检测领域的一个经典两阶段检测器（2015 年），发明了 RPN（区域建议网络），首次把“找候选框”和“分类框”放进同一个网络里端到端训练。

它是 YOLO 的“前辈”，但走的是一条完全相反的技术路线。

#### 先理解“两阶段”是什么意思

你熟悉的 YOLO 是单阶段的：一次前向传播，直接输出框和类别。

Faster R-CNN 是两阶段的，分两步走：

```
第一步（粗筛）：先找出这些地方“可能有目标”，给出候选框
        ↓
第二步（精修）：对每个候选框，仔细判断“是什么类别”、“框再微调一下”
```

**可以类比成：**  先在整张图上“圈出可疑区域”，再对每个区域“仔细鉴定”。

#### 它的核心创新：RPN

**Faster R-CNN 最有名的贡献就是 RPN（Region Proposal Network，区域建议网络）。**

**在它之前（R-CNN、Fast R-CNN），找候选框用的是传统方法 Selective Search，非常慢。**  Faster R-CNN 的突破是：

> **让网络自己学会“哪里可能有目标”，而不是靠外部算法找。**  而且这件事和后面的检测共享同一套特征，所以速度大幅提升。

**RPN 的工作方式：**

```
特征图上每个位置，放一组预先设计好的“锚框”（anchor，不同大小、不同长宽比）
        ↓
RPN 判断每个锚框：这里有没有目标？框要不要微调？
        ↓
筛出分数高的锚框作为候选（proposal）
```

**这个“锚框 + 偏移微调”的思路，后来也被 YOLO 借鉴了。**  现在用的 YOLO26n 的检测头，本质上也有类似的锚框/中心点匹配机制。
